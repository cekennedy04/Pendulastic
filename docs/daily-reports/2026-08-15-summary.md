* **Errors & Troubleshooting:**
  * **Validation split silently empty:** `VAL_PARTICIPANTS` still held pre-reorg leg/condition-qualified names (`"Participant_5_left_side"`); since the 08-04 "simplified recording folder structure" reorg, `gen_training_data.py` emits bare `"Participant_N"`, so the held-out set never matched — unnoticed because the corpus hadn't been regenerated since. Fixed to bare IDs; verified a real split (11,085 val across Participants 5 & 8, 23,799 train across the other 11). Every val metric from the old corpus era is suspect.
  * **0.456s IMU-vs-RGB start skew:** source dispatch ran in list order, so OptiTrack's blocking Motive handshake ran before RGB capture started. Fix: trigger OptiTrack last; verified with a standalone timing harness against a dummy Motive responder (0.456s → 0.000s).
  * **Motive recording into the wrong session:** the START packet omitted `relpath`, so `motive_sync.mirror_relpath()` silently skipped `SetCurrentSession` and recordings landed in whatever session Motive last had open. Now mirrors `master_app.py`'s folder layout.
  * **Batch thread death:** one corrupt trial (bad frame, disk full) would kill the whole worker, leaving remaining trials stuck at `status="processing"` and the form permanently locked. Per-entry try/except now falls back to the trial's originally recorded series.
  * **Phase 1 restarts from zero:** on the bigger corrected dataset, Phase 1 alone outlives the environment's job-killer, and only a completed-Phase-1 checkpoint existed — every kill meant restarting from epoch 0. Per-epoch partial checkpoint + `initial_epoch` resume, verified with a kill/resume smoke scenario.
* **Key Learnings:**
  * Constants that encode filesystem layout (like `VAL_PARTICIPANTS`) rot silently when the layout changes — an empty-val-split assertion in the training script would have caught this ten days ago. Related: any val-RMSE numbers reported while the split was empty need re-baselining.
  * In a multi-source start sequence, a blocking handshake taxes every source dispatched after it — order the blocking call last, and mirror the reference implementation (`master_app.py`) rather than re-deriving.
  * Stale comments are latent bugs: the "runs before" docstring could have invited someone to reintroduce the exact UI-freeze this code was restructured to avoid. The pre-push review of the unpushed commit range caught it (and the worker-crash bug).
