The device report "beeps fire while settling but never while holding" turned out to be arithmetically guaranteed: `calm_s` tops out at 0.95 before the state turns Ready, so `Math.floor(calm_s)` is always 0 and no per-second beep is ever due. The hold is sub-second, so it is now edge-signalled instead: a tick on hold start/restart, a distinct two-note rise for "ready to release" (previously missing entirely, and the cue that matters most when the operator's eyes are on the leg), and the existing settle count + completion tone for "ready to stop." Verified in-browser by replaying the real state sequence.
* **Errors & Troubleshooting:** The hold-beep bug was not a wrong threshold but the wrong instrument — a whole-second counter applied to a phase shorter than one second. The regression test pins the arithmetic over every value `calm_s` can take, including its ceiling, because a test on the counter alone would not have caught it. The new cues are edge-triggered on the state code; without that, the 50 ms tick loop would re-fire them continuously.
