* **Errors & Troubleshooting:**
  * **Every failed IndexedDB write reported "Save failed: null"** — `db.js` `put()` rejected with `tx.error`, which is still null while the transaction is merely erroring, so the duplicate-assessment recovery message (which reads `err.name`) could never appear. Fixed to prefer the request's error on both the error and abort paths — fixes reporting for every writer, not just MAS.
  * **MAS drafts silently prefilled blank** — drafts were saved under the form's leg but loaded under the session's side, which diverge the moment the clinician changes the Leg field. Loading now scans the participant's bounded candidate key set and resumes the newest by `saved_at`.
  * **`isCapturing` can't come from the session handle** — `app.js` nulls it across the whole iOS permission-prompt window, so the router would have permitted navigation while a capture was starting. Derived from `#stop` visibility instead, with a test pinning that the handle-based derivation is wrong.
  * **Resize on any other view redrew the waveform canvas at 0×0** — the redraw was gated on `#waveform-wrap.hidden`, which doesn't see the section's visibility; now gated on the view being active.
  * **Spec said "reuse the capture scoring path" — it doesn't exist** — that path is a method on a live `WasmSession` with samples pushed in; there's no params → score veneer entry. Amended to export `pt_score_from_params` (nine named args so a mis-ordered call is a compile error), with the known cost of one `ALGORITHM_VERSION` bump.
  * **Plan self-review caught its own defect pre-commit** — Task 6 duplicated Task 4's `chartScale` maths inline and carried a real bug: the MAS axis needs a fixed 0–5 ordinal domain or a participant scoring only 1–2 renders as if that were the whole scale.
* **Key Learnings:**
  * Author-origin display rules silently defeat the `hidden` attribute — a dedicated `.active` class can't be defeated the same way (why the shell toggles classes).
  * Distinguish "never chosen" from "deliberately cleared" with a present-but-null settings row — deleting the row would re-adopt the just-closed lone participant on exactly the device where that's likeliest.
  * `sessionStorage` is cleared exactly when a standalone PWA is terminated — the eviction-then-relaunch case a draft exists to survive — so drafts belong in IndexedDB.
  * Show `BUILD_ID`, not a git revision, on-device: it's the SW cache key, so matching it against the deployment proves the phone runs exactly those bytes; a commit containing its own generated stamp can't exist (the `ALGORITHM_VERSION` off-by-one again). Motivated by a full smoke-test pass invalidated by unknowingly testing production's old UI.
  * Build rows with `createElement`, never `innerHTML` — participant identifiers are clinician-typed free text reaching the DOM via trial records.
  * Record clinical-safety objections in the spec even when overruled: the PT7 time-axis chart ships as asked, but the objection, alternatives, and mitigations are on the record.
