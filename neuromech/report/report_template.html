Pendulastic · Aim 3 · research report · 26 Oct 2026

A knee spasticity emulator on the motor rig

How to program the existing LabVIEW motor rig to reproduce a pendulum test at any spasticity level, with odd behaviours and out-of-range values for each of the seven Popović parameters, so the phone app can be tested against a leg whose answer is known.

Built on the team's Notion design (the pendulum equation and the metric-to-controller table), the validated De Groote 2018 model already ported on feat/pendulum-sim-validation, this autumn's bench characterisation, and new literature. All code, scenario files and figures are in neuromech/.

The short answer

Build it in three modes. First, a scenario player: the model runs offline in Python, LabVIEW plays the resulting 1 kHz angle file through the existing position loop, and the encoder log scores every run. That needs one new LabVIEW capability, a setpoint-array input, plus a re-tune and feedforward, because the rig as tuned today over-renders anything above 3 Hz. Then put the same model in the real-time loop (verified Formula Node code is ready). Last, run it in torque mode on a real shank on the vertical rig, where the motor supplies only the muscle torques.

1. What the emulator has to do

Patients cannot be programmed. A motor can. The emulator's job is to produce pendulum swings whose true parameters are known, so that three questions get clean answers.

  • Does the phone measure what the leg did? Every run is scored twice through the same production scorer, once from the 1 kHz encoder (truth) and once from the phone. This extends the bench accuracy work (0.58° static, 0.4 % ring frequency) from steps and rings to real pendulum-test swings.
  • Does the app grade correctly at every severity? A programmed MAS ladder tests grade agreement at each level, which the clinic cannot supply on demand (77 % of our clinical legs are MAS 0).
  • Does the app refuse or flag what it should? Each of the seven parameters, and the excursion gate, can be pushed past its bounds one at a time to check every flag and refusal path.

A fourth use, interactive training for physical therapists, comes later, in Mode B with the torque sensor in the loop.

2. The model

The team's Notion page already states the right equation, and the repository already contains a tested implementation of it. It is De Groote et al. 2018, which explains the three hallmark pendulum-test features in spastic cerebral palsy (smaller first drop, fewer swings, a non-vertical rest) with three mechanisms: baseline tone, short-range stiffness on the first drop, and a delayed force-feedback stretch reflex. The port was checked against the authors' own MATLAB and passes 21 tests.

J·θ̈ + B·θ̇ + mgl·cos(θ + incline) + Twall(θ) = Ttone + TSRS + Treflex + Tmodules inertia, passive damping, gravity (thigh inclined so the leg rests near 125°) and soft range walls, against the muscle torques. Reflex: delayed 50 ms, driven by the SRS and damping torques, 10 ms activation.

On top of the published terms, model_rt.py adds nine modules for behaviours the paper does not model. Each is off by default, so with all of them at zero the model is exactly the published one.

Making it run in LabVIEW

The published code integrates with RK4 and cubic-Hermite delay reads. A real-time loop needs something simpler, so the portable model uses a fixed 1 ms step, an integer ring buffer for the 50 ms delay, and tanh blends in place of erf (the Formula Node has no erf). Against the published model it stays within 0.000° passive, 0.03° nominal spastic and 0.30° strong spastic over 10 s. The Formula Node form, four explicit Euler substeps per tick, stays within 0.34°. The Formula Node text itself was executed against Python test vectors and matches to 1×10⁻¹¹ on every state.

One bug found on the way is worth carrying into the LabVIEW build. The ring buffer must be 52 samples long, not 51. With 51, the "one sample older" index wraps onto the newest sample, the delayed derivative becomes garbage, and the reflex runs away by about 270°.

3. The scenario library

scenarios in five groups, each a setpoint file the rig can play and a row of expected scorer output. Out-of-range cases use exact kinematic transforms where the physics would change several parameters at once. Time-scaling moves only f and the two velocity terms. Amplitude-scaling moves only A0. A slow drift of the resting angle moves only where the scorer thinks the leg rests.

The MAS ladder is calibrated by bisection along the published severity axis (tone 2λ N·m, kf 0.75λ, kdf 0.025λ) to the centre of each PT7 band: λ = 0.166, 0.379, 0.500, 0.587 and 0.654 for MAS 0, 1, 1+, 2 and 3. The passive model scores like our controls before any tuning: f 0.915 Hz against the healthy reference 0.914, rest 124.9° against the controls' ~125°, φmax 0.645 against 0.639.

4. What the emulator already says about the scorer

These come from running the scenarios through the production scorer, before any hardware run. Each is a concrete test case the rig can now reproduce on demand.

inversion

PT7 is non-monotonic along the published severity axis (figure above). Severe legs grade milder, or are refused. This matches the U-shaped relaxation index Whelan et al. report at MAS 3. A monotonic grade map cannot be calibrated past MAS 2 on PT7 alone.

rest drift

A healthy leg whose resting angle creeps 3 °/s after it has settled grades MAS 4 (area ratio 0.84). This is the same failure seen with the phone on 2026-09-08, now reproduced with a perfect sensor. The scorer needs a settled-tail check, not only a better phone.

missed

A clasp-knife catch grades MAS 0, a contracture grades MAS 0, and a leg that is not relaxed (guarding) grades MAS 0 with no warning. The literature's relaxation check, by EMG or phase plane, is still absent.

wrong disorder

Lead-pipe rigidity grades MAS 1 with f = 0 (one swing). Rigidity and spasticity both read as "spastic", and the near-linear decay that tells them apart is not used.

clonus

Clonic beats make the leg look milder (PT7 0.30 against 0.36 without clonus), because extra beats raise N. A 6 Hz beat is only ten phone samples per cycle at the gyro's ~60 Hz.

anthropometry

The same healthy swing played 2× faster or slower (a shorter or longer leg) grades MAS 1. f and ωmax are compared with an adult reference without any correction for leg length.

plausibility

φmax is capped at exactly 1.000 when energy is injected on the return, rather than flagged as impossible for a passive leg. The 2 Hz frequency flag and both excursion refusals do fire as designed.

protocol

Stopping the recording 3 s after release grades a healthy leg MAS 1. Five repeated drops with a habituating reflex drift one grade, from MAS 2 to 1+.

5. Can the rig render it?

Three constraints, all measurable now.

  • Range. In clinical geometry the leg is released 55° above where it hangs and swings 35–52° below it. 42 of the 45 scenarios exceed today's ±45° software limits. Confirm the arm's mechanical range and set ±65°. Failing that, render at 0.75× amplitude: A0 stays above the 25° gate, and every ratio parameter is amplitude-invariant.
  • Speed. The clinical scenarios need 160–330 °/s. The rig has already reached 440 °/s. Only the deliberately extreme kinematic cases (560–700 °/s) are score-only.
  • Tracking. Measured from the setpoint and encoder already in 23 SSR logs: the arm follows the command at 1 Hz, overshoots it by 10 % at 2 Hz and 26 % at 3 Hz, by about 2× at 5 Hz, and resonates at 6.35 Hz. That is exactly the band of the spastic catch and clonus.

6. The LabVIEW program

Everything is an addition to the existing StretchExperiment host and real-time project. The full specification is neuromech/labview/LABVIEW_PROGRAM_SPEC.md.

Mode A · now

Scenario player

Reads a 1 kHz setpoint file (angle, velocity and acceleration feedforward, phase) and plays it through the existing position PID. Needs a setpoint-array input, feedforward, and four safety trips. Every file starts with the shared sync-pulse and minimum-jerk preamble from motor_reference.py.

Mode B · next

Model in the loop

The Formula Node model integrated each tick, with its angle as the setpoint. Parameters live on the front panel. Adding the torque sensor's reading to the model makes it interactive, so a PT can feel the virtual leg (admittance rendering).

Mode C · vertical rig

Muscles on a real shank

Torque control supplies only tone, SRS, reflex and module torques; gravity and inertia are physical. Needs about 4 N·m for MAS 0–3, 15 N·m for severe legs and 26 N·m for real-size clonus, so a gearbox. This is the only mode in which the app's fused angle can be graded.

A session

  1. Zero and arm the rig as today.
  2. Run the 20 s chirp (0.2–10 Hz, ±8°) to identify the plant and the feedforward gains. Stop if the resonance has moved more than 10 % since the last session.
  3. Play the MAS 2 preset ten times to measure repeatability.
  4. Play the ladder in random order, three times each, then the behaviours, out-of-range cases and artefacts. For each run: start the phone, start the log, play the file, let the app auto-stop, stop the phone, stop the log.
  5. Run the ILC tool on any scenario whose delivered PT7 left its band, and play it again.

Acceptance per scenario, encoder-scored: delivered PT7 inside the intended band, each parameter within the bench MDC95, tracking RMSE under 1°. The phone is then compared run by run against the encoder-scored parameters.

8. What the literature supports

Model choice. He et al. 1997 showed no single stretch-reflex parameter spans the severity range; simultaneous gain and threshold changes do. That is why the ladder moves tone and both gains together. Le Cavorzin et al. 2001 and Fee & Foulds 2004 fitted pendulum-test models with separate agonist and antagonist terms, the basis for the flexor module and area-ratio asymmetry. De Groote et al. 2018 is the only model shown to reproduce all three hallmark kinematic features, so it is the engine. Willaert et al. 2024 identify neural and non-neural parameters per patient from instrumented tests, which is the route to patient-derived presets (decision 6).

Robotic precedents. The Haptic Elbow Spasticity Simulator recreated MAS 1, 1+, 2 and 3: clinicians reached 100 % agreement with the source patients, and inter-rater agreement was substantial (κ ≈ 0.63–0.65). Park et al. 2017 parameterised each MAS grade with three characteristics. Pei et al. 2023 rendered spasticity, lead-pipe and cogwheel rigidity on a series-elastic arm and clinicians classified them with more than 87 % accuracy. Cooney et al. 2022 used a humanoid robot to evaluate IMU-based spasticity measurement. All are elbow or upper-limb devices driven by a clinician's hand; none emulates a knee pendulum test, where the motion comes from gravity and the device must render a free swing.

What the pendulum test can detect. Whelan et al. 2018 (131 knees) found the metrics separate MAS 0 from MAS > 0 but cannot grade severity. They also found the relaxation index U-shaped at MAS 3, which the emulator reproduces in PT7. Aleksić et al. 2021 proposed a pendulum-based scale that also types the spasticity (flexion or extension), which the flexor and extensor modules can now test.
